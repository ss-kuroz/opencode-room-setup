# Amp Room Setup

Reproducible configuration for a three-role Amp room (SLP: Supervisor, Lead,
Peer) running through an **operator-installed** Paseo daemon:

```text
Paseo daemon (installed on the machine, ~/.paseo/config.json)
  -> daemon.agentProfiles "amp-supervisor | amp-lead | amp-peer"
       provider amp-acp, mode local, auto_accept
  -> amp-acp (ACP adapter) -> Amp CLI (effort medium / high / low)
  -> shared contract at ~/.config/amp-room/workflow/WORKSPACE_PROTOCOL.md
```

This repository does **not** install Paseo, Amp, or `amp-acp`, and it does not
manage any of their state. It owns exactly three things and re-applies them
idempotently:

| Repository source | Local destination |
| --- | --- |
| `config/room.json` + `roles/*.md` | `~/.paseo/config.json` → provider `amp-acp` and the three `daemon.agentProfiles` entries |
| `workflow/WORKSPACE_PROTOCOL.md` | `~/.config/amp-room/workflow/WORKSPACE_PROTOCOL.md` |
| (backup of every config it rewrites) | `~/.amp-room-backups/` |

Everything else in `~/.paseo/config.json` — daemon settings, other providers,
other agent profiles, plugins — is preserved untouched. Sync never restarts
the daemon; it asks a running daemon to `reload` its config.

## Prerequisites

- Paseo installed, onboarded, and running (`paseo daemon status`).
- Amp CLI installed and logged in (`amp`), plus the ACP adapter on PATH
  (`npm install -g amp-acp`).
- Python 3.11+ (stdlib only).

## Usage

```bash
python scripts/room.py sync      # publish provider + profiles + protocol, reload daemon
python scripts/room.py verify    # read-only check of repo sources and installed state
python scripts/room.py verify --source   # source-only check, no HOME access
python scripts/room.py uninstall # remove exactly the managed artifacts
make test                        # unit tests for the merge/render logic
```

`sync` is idempotent and is also the repair path: if the Paseo Desktop UI
deletes or edits a room profile, re-run `sync` to restore it. Profile `id`s of
existing same-named profiles are preserved, so agents and schedules referencing
them keep working.

## Roles

| Profile | Provider | Model (effort) | Mode | Auto-accept |
| --- | --- | --- | --- | --- |
| `amp-supervisor` | `amp-acp` | `medium` | `local` | yes |
| `amp-lead` | `amp-acp` | `high` | `local` | yes |
| `amp-peer` | `amp-acp` | `low` | `local` | yes |

Human retains product, cost, external-effect, and irreversible-risk decisions.
Supervisor routes Human intent and bounded recovery. Lead owns technical
framing, dependency order, verification, and explicit candidate acceptance.
Peer owns one bounded outcome and returns an immutable candidate or a concrete
block signal. Role authority lives in `roles/*.md`; the shared coordination
contract lives in `workflow/WORKSPACE_PROTOCOL.md`. Read
[docs/architecture.md](docs/architecture.md) before changing these boundaries.

## Where to edit

- Role prompt or authority: `roles/<role>.md`.
- Model, mode, auto-accept, or profile names: `config/room.json`.
- Shared coordination rules: `workflow/WORKSPACE_PROTOCOL.md`.
- Merge/render behavior: `scripts/room.py` and `tests/test_room.py`.

Never hand-edit `~/.paseo/config.json` room entries; they are regenerated. No
secret, session, log, or keypair belongs in this repository.

## History

This repository previously built a Codex room: per-role `CODEX_HOME` runtimes
generated by `codex-room-sync`, and a Paseo checkout built from a pinned source
release. The Amp refactor replaced that machinery — roles are now Paseo agent
profiles on the `amp-acp` provider, and Paseo is operator-installed. See
[docs/architecture.md](docs/architecture.md) for the current design and
`git log` for the previous one.
